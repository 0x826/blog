    场景设计 · 面试 · 前端

    模块一：极致性能优化

    1. 10 万条长列表渲染卡顿，如何优化到丝滑滚动？

    • 核心方案：虚拟滚动（Virtual Scrolling）。只渲染可视区域（Viewport）及上下缓冲区（Buffer）的 DOM 节点。
    • 实现细节：监听 scroll 事件（需节流/requestAnimationFrame），计算 startIndex 和 endIndex。使用一个撑开总高度的“占位容器”，通过 transform: translateY() 或 padding 定位可视节点。
    • 进阶优化：动态高度计算（预估高度+渲染后修正）、使用 ResizeObserver 监听尺寸变化、将滚动计算移至 Web Worker。

    2. 首屏加载慢，系统性优化到 2 秒以内？

    • 网络层：开启 HTTP/2、Brotli 压缩、CDN 边缘缓存、DNS 预解析。
    • 资源层：路由级/组件级代码分割（Lazy Loading）、图片 WebP/AVIF 格式及响应式图片、关键 CSS 内联（Critical CSS）、非关键资源 defer/async。
    • 渲染层：SSR/SSG 直出 HTML、骨架屏（Skeleton）占位、预加载关键资源（<link rel="preload">）、减少主线程阻塞（长任务切片）。
    • 指标关注：优化 LCP（最大内容绘制）、FCP（首次内容绘制）、INP（交互到绘制延迟）。

    3. 长任务导致页面卡顿，如何不阻塞主线程？

    • 时间切片：将长任务拆分为多个小于 50ms 的子任务，使用 requestIdleCallback 或 MessageChannel 在浏览器空闲时执行。
    • Web Worker：将纯计算（如大数据排序、JSON 解析、加密解密）移至 Worker 线程，通过 postMessage 通信。
    • 并发控制：使用 requestAnimationFrame 处理动画，避免与主线程渲染竞争。

    4. 图片懒加载与预加载策略设计

    • 懒加载：使用 IntersectionObserver 监听图片进入视口，再替换 src；或直接使用原生 <img loading="lazy">。
    • 预加载：对首屏关键图片使用 <link rel="preload" as="image">；对鼠标 Hover 或即将滑入视口的图片，在 JS 中 new Image().src = ... 提前下载。

    5. 骨架屏与首屏体验优化

    • 原理：在 HTML 中内联一段与真实布局一致的 CSS 占位块，在 JS 下载和执行期间展示。
    • 进阶：使用工具（如 page-skeleton-webpack-plugin）在构建时自动生成骨架屏；或使用 SVG 动画骨架屏提升视觉体验。结合 SSR 的 fallback 机制实现无缝切换。

    6. 前端性能监控指标采集（Web Vitals）

    • 采集方案：使用官方 web-vitals 库。
    • 核心指标：LCP（使用 PerformanceObserver 监听 largest-contentful-paint）、FID/INP（监听 event 处理耗时）、CLS（监听 layout-shift）。
    • 上报：使用 navigator.sendBeacon 在页面卸载时异步上报，避免阻塞页面关闭。

    模块二：监控、埋点与排查

    7. 线上偶发白屏，如何系统排查与防治？

    • 检测：1) 采样检测关键 DOM 节点（如 #root 下的子节点是否为空）；2) 使用 MutationObserver 监听 DOM 变化；3) 捕获 window.onerror 和 unhandledrejection。
    • 排查：通过错误监控平台获取 StackTrace，结合 SourceMap 还原源码；查看用户操作轨迹（如使用 rrweb 录屏回放）；检查网络请求是否被 CORS 或 5xx 阻断。
    • 防治：完善 ErrorBoundary、接口异常降级（Fallback UI）、核心链路增加重试机制。

    8. 统计页面停留时长与元素曝光

    • 停留时长：在 visibilitychange 事件中记录时间差；结合 mousemove/scroll/keydown 判断用户是否真实活跃（剔除挂机）。
    • 元素曝光：使用 IntersectionObserver 监听目标元素，当 intersectionRatio > 0 且持续一定时间（如 500ms）时，标记为有效曝光并上报（需做防抖和去重）。

    9. 前端埋点 / 监控 SDK 设计

    • 架构：分为数据采集层（无埋点/声明式/命令式）、数据处理层（清洗/聚合/队列）、上报层（sendBeacon/批量上报/重试机制）。
    • 无埋点：通过代理原生事件（如重写 addEventListener）或全局监听，自动采集点击/曝光数据，结合 AST 在编译时注入组件 ID。
    • 设计原则：非侵入式、高可用（SDK 报错不能影响业务）、支持 Tree-shaking、插件化扩展。

    10. 前端错误监控与上报

    • 捕获：window.onerror（同步/资源加载）、unhandledrejection（Promise）、ErrorBoundary（React 渲染）、Vue errorHandler。
    • 上下文：上报时附带用户 UA、路由、Redux/Vuex 状态快照、最后 N 次网络请求。
    • 还原：构建时上传 SourceMap 到监控平台，上报时只传行列号，平台自动还原真实代码位置。

    模块三：网络、通信与缓存

    11. 大文件上传（分片 / 断点续传 / 秒传）

    • 分片：使用 File.slice() 将文件切分为固定大小（如 5MB）的 Blob。
    • 并发控制：使用并发限制器（如 p-limit）控制同时上传的分片数，避免占满浏览器连接池。
    • 秒传：上传前使用 SparkMD5（建议在 Web Worker 中计算）计算文件 Hash，发给后端校验，若已存在则直接返回成功。
    • 断点续传：后端记录已上传的分片 Index，前端请求后端获取已上传列表，跳过已上传分片继续传。

    12. WebSocket 实时消息（断线重连 / 心跳 / 消息有序）

    • 心跳保活：前端定时发送 Ping，后端回复 Pong。若超时未收到 Pong，判定断线。
    • 断线重连：采用指数退避算法（如 1s, 2s, 4s, 8s… 最大 30s）进行重连，避免雪崩。
    • 消息有序/不丢：引入消息序列号（Seq）。前端发送带 Seq，后端按 Seq 排序处理；后端推送带 Seq，前端若发现 Seq 不连续，主动请求拉取缺失消息。

    13. 多 Tab 页通信与数据同步

    • 方案：BroadcastChannel（同域 Tab 广播）、localStorage 监听（storage 事件）、SharedWorker（共享 Worker 线程）、ServiceWorker 消息控制。
    • 场景：一处登录多处踢出、购物车数据同步、主题切换同步。

    14. 前端缓存策略设计（接口缓存 + 数据持久化）

    • 接口缓存：HTTP 缓存（强缓存/协商缓存）；应用层缓存（使用 axios 拦截器 + Map/localStorage 实现接口级缓存，设置 TTL 过期时间）。
    • 数据持久化：localStorage（<5MB）、IndexedDB（大容量/结构化数据，配合 idb 库）、Cookie（需随请求发送的小数据）。

    15. 并发请求控制与请求竞态（取消）

    • 并发限制：实现一个 asyncPool，维护一个执行队列，保证同时执行的 Promise 不超过 N 个。
    • 竞态取消：使用 AbortController。在发起新请求前，调用 controller.abort() 取消上一个未完成的请求，防止旧数据覆盖新数据（如搜索框联想）。

    16. 列表页与详情页数据预取与缓存

    • 预取：在列表页 Hover 列表项，或鼠标移向详情页按钮时，提前触发详情页接口请求（Prefetch）。
    • 缓存：使用 React Query / SWR 等库，实现接口数据的内存缓存、后台静默刷新（Stale-While-Revalidate）、详情页返回列表页时瞬间恢复数据。

    模块四：架构、工程化与基建

    17. 权限系统设计（菜单 + 按钮级）

    • 菜单级：后端返回权限树，前端动态生成路由表（addRoute），或前端根据权限标识过滤路由配置。
    • 按钮级：1) 自定义指令（Vue）或高阶组件（React）包裹；2) 全局权限函数 checkPermission('btn:add') 控制 v-if 或 disabled。
    • 安全兜底：前端只做展示拦截，核心接口后端必须做二次鉴权。

    18. 微前端拆分与应用间通信

    • 方案选型：qiankun（基于 single-spa，JS 沙箱）、Module Federation（Webpack 5 原生，模块级共享）、Wujie（基于 iframe + WebComponent，隔离彻底）。
    • 通信：全局状态管理（如 initGlobalState）、CustomEvent 自定义事件、URL 参数、SharedWorker。
    • 隔离：JS 沙箱（Proxy 代理 window）、CSS 隔离（Shadow DOM、BEM 命名空间、postcss 加前缀）。

    19. 设计一个可插拔的前端 SDK

    • 核心设计：1) 核心层（Core）保持极简；2) 插件机制（Plugin），通过 use(plugin) 注册，插件可访问核心上下文；3) 生命周期钩子（beforeInit, afterInit）。
    • 工程化：支持 ESM/CJS/UMD 多格式输出，支持 Tree-shaking，提供完整的 TypeScript 类型推导。

    20. 前端国际化 i18n 方案设计

    • 方案：使用 react-i18next 或 vue-i18n。语言包按模块拆分（JSON/TS）。
    • 优化：1) 按需加载：路由级动态 import() 语言包；2) 编译时优化：使用 Babel 插件提取硬编码中文，生成语言包；3) 兜底策略：缺失翻译时 fallback 到默认语言或显示 Key。

    21. 主题换肤与深色模式方案

    • CSS 变量：在 :root 定义 CSS Variables，通过 JS 切换 html 标签的 data-theme 属性，触发变量值切换。
    • CSS-in-JS：使用 ThemeProvider 注入主题对象，组件内通过 props.theme 读取。
    • 深色模式：优先使用 @media (prefers-color-scheme: dark) 跟随系统，提供手动切换开关覆盖系统设置，存入 localStorage。

    22. 低代码 / 可视化搭建平台思路

    • 核心架构：1) 物料中心（组件库+描述协议 JSON Schema）；2) 画布引擎（渲染器+拖拽交互）；3) 设置面板（属性/事件/数据源配置）；4) 出码引擎（将 JSON 转换为 React/Vue 源码）。
    • 协议设计：定义标准的组件描述协议（如阿里 lowcode-engine 协议），包含组件标识、属性、事件、生命周期、数据源。

    23. 设计一个组件库

    • 架构：Monorepo 管理（pnpm workspace），按组件拆包。
    • 规范：统一的 API 设计（Props 命名、受控/非受控）、主题定制（CSS 变量）、无障碍（a11y/ARIA 属性）。
    • 工程：使用 Vite/Rollup 构建，生成 ESM/CJS/Types，提供完整的 Storybook 文档和单元测试。

    24. 跨端方案选型（H5 / RN / Flutter / 小程序）

    • H5：兼容性最好，性能一般，适合营销页、轻交互。
    • React Native：复用 React 生态，原生渲染，适合需要深度定制原生能力的 App。
    • Flutter：自绘引擎（Skia），UI 一致性极高，性能接近原生，适合从零构建高颜值 App。
    • 小程序/Taro/uni-app：依托超级 App 流量，开发快，适合电商、O2O 等轻量级业务。

    25. 前端灰度发布与 AB 测试 / 功能开关（Feature Flag）

    • 灰度：Nginx 层根据 Cookie/IP/用户 ID Hash 分流，指向不同版本的静态资源；或结合 Service Worker 动态拉取不同版本的 JS。
    • Feature Flag：接入配置中心（如 Apollo/LaunchDarkly），前端 SDK 启动时拉取开关配置，结合 React Context 或高阶组件控制代码块渲染。

    26. 前端降级与容错

    • 降级：核心接口超时或报错时，展示兜底 UI（如默认数据、缓存数据）；非核心组件（如评论、推荐）加载失败时静默隐藏，不影响主流程。
    • 容错：全局 ErrorBoundary 捕获渲染崩溃；接口层统一拦截 5xx 并提示；关键操作增加本地重试机制。

    模块五：复杂业务与交互

    27. SSR 项目架构设计

    • 架构：Node.js (Express/Koa/NestJS) 作为 BFF 层，负责路由匹配、数据预取、调用 React renderToString。
    • 优化：流式 SSR（renderToPipeableStream，React 18+）、结合 CDN 缓存 HTML、关键 CSS 内联、客户端 Hydration 按需加载。

    28. SPA 路由与 SEO 问题

    • 问题：SPA 初始 HTML 为空，爬虫无法抓取内容。
    • 解决：1) SSR/SSG（Next.js/Nuxt.js）；2) 预渲染（Prerender SPA Plugin），构建时生成静态 HTML；3) 针对 SEO 单独做一套传统 MPA 或使用 SSG 生成静态页面。

    29. 富文本编辑器选型与 XSS 防护

    • 选型：Slate.js（高度可定制、React 友好）、Quill（成熟、生态好）、TinyMCE（传统、功能全）。
    • XSS 防护：1) 提交前/渲染前使用 DOMPurify 过滤恶意标签（如 <script>, onerror）；2) 渲染时使用 dangerouslySetInnerHTML 必须确保内容已清洗；3) 配置 CSP 限制内联脚本执行。

    30. 前端安全防护整体方案

    • XSS：输入过滤、输出转义、CSP、HttpOnly Cookie。
    • CSRF：SameSite Cookie 属性、Anti-CSRF Token、验证 Origin/Referer。
    • 点击劫持：X-Frame-Options: DENY 或 CSP frame-ancestors。
    • 敏感信息：不在前端硬编码密钥，Token 避免存入 localStorage（防 XSS 窃取），推荐 HttpOnly Cookie。

    31. 防止重复提交

    • 前端：按钮点击后立即 disabled 或显示 Loading；使用 lodash debounce/throttle；Axios 拦截器中通过请求 URL+参数生成 Hash，拦截重复请求。
    • 后端：接口幂等性设计（唯一索引、分布式锁、Token 机制），前端防重只是辅助。

    32. 复杂表单设计（动态表单 / 联动 / 校验）

    • 方案：使用 React Hook Form 或 Formik。采用 JSON Schema 驱动表单渲染。
    • 联动：通过 watch 监听字段变化，动态修改其他字段的 options 或 rules。
    • 校验：支持同步校验、异步校验（如检查用户名是否重复，需防抖）、跨字段联动校验。

    33. 大数据量表格（虚拟滚动 + 固定列 + 排序筛选）

    • 虚拟滚动：使用 react-window 或 ag-grid，只渲染可视行。
    • 固定列：利用 CSS position: sticky，配合 z-index 和阴影效果。
    • 排序/筛选：若数据量极大（>1万），将排序/筛选逻辑移至 Web Worker 或后端处理，避免阻塞主线程。

    34. 秒杀页面设计

    • 前端：倒计时使用本地时间校准（服务端时间 - 本地时间 = 差值）；按钮防抖、点击后置灰；静态资源全量 CDN 缓存；接口请求增加验证码或动态 Token 防刷。
    • 体验：骨架屏、Loading 动画、库存不足时的友好提示。

    35. 上传图片压缩与裁剪

    • 压缩：使用 Canvas.drawImage 重绘图片，通过 canvas.toBlob 调整 quality 参数压缩；或使用 browser-image-compression 库（底层基于 Canvas/OffscreenCanvas）。
    • 裁剪：使用 react-cropper（基于 Cropper.js），获取裁剪区域的坐标和尺寸，在 Canvas 中截取并导出。

    模块六：补充遗漏的高频/前沿架构题（2024-2026 核心考点）

    36. Monorepo 架构设计与工程化落地

    • 选型：pnpm workspace + Turborepo/Nx。
    • 优势：代码共享（提取公共组件/工具库）、统一依赖管理、原子化提交（保证多包版本一致性）。
    • 痛点解决：使用 Turborepo 实现增量构建和远程缓存，解决 Monorepo 随着项目变大导致 CI/CD 极慢的问题；使用 changesets 管理多包版本发布。

    37. 前端构建速度深度优化（Webpack/Vite）

    • Webpack：1) 缩小搜索范围（resolve.alias, include）；2) 开启持久化缓存（cache: { type: 'filesystem' }）；3) 使用 esbuild-loader 替代 babel-loader；4) 多线程构建（thread-loader）。
    • Vite：利用 esbuild 进行预构建（依赖预打包）；开发环境基于原生 ESM，按需编译；生产环境使用 Rollup 打包。

    38. BFF (Backend For Frontend) 架构设计

    • 定位：前端自己控制的 Node.js 中间层，用于接口聚合、数据裁剪、格式转换。
    • 场景：移动端与 PC 端共用后端微服务时，BFF 负责将多个微服务接口聚合为一个，减少前端请求数（解决瀑布流）；处理后端接口返回的冗余字段，减少传输体积。
    • 技术栈：NestJS / Midway / Express + GraphQL (可选)。

    39. 全链路追踪：Trace ID 如何贯穿前后端？

    • 生成：前端在请求拦截器中生成唯一的 Trace-Id（或从 Cookie/全局状态获取），注入到 HTTP Header 中。
    • 透传：Nginx 或 API 网关接收后，将其透传给后端微服务；后端服务间调用（RPC/HTTP）继续透传。
    • 闭环：前端发生错误或接口超时，上报错误日志时携带 Trace-Id。排查时，通过 Trace-Id 在 SkyWalking/Jaeger 中还原完整调用链路。

    40. 线上疑难杂症排查：内存泄漏与 CPU 飙高

    • 内存泄漏：使用 Chrome DevTools Memory 面板，拍摄 Heap Snapshot。对比操作前后的快照，查找 “Detached DOM tree”（分离的 DOM 节点）或被闭包/全局变量意外引用的大对象。常见原因：未清理的定时器、未取消的事件监听、闭包引用。
    • CPU 飙高：使用 Performance 面板录制（Record），查看 Main 线程的火焰图（Flame Chart），定位长任务（Long Tasks）或高频触发的函数（如未节流的 scroll/resize 事件、死循环）。

    41. 前端接入大模型 (LLM)：SSE 流式输出与状态管理

    • 通信：使用 fetch API 配合 ReadableStream 处理 Server-Sent Events (SSE)。逐块读取 TextDecoder 解码的数据。
    • 渲染优化：流式数据会导致 React 频繁重渲染。必须使用 useTransition 或 useDeferredValue 将打字机效果的渲染标记为低优先级，保证输入框等 UI 的响应性。
    • 中断：使用 AbortController 实现“停止生成”功能。

    42. 前端敏感数据 (Token/密钥) 安全存储与流转

    • 存储：绝对不要将敏感 Token 存入 localStorage（易受 XSS 攻击）。推荐存入 HttpOnly + Secure + SameSite=Strict 的 Cookie 中，由浏览器自动携带，JS 无法读取。
    • 流转：Access Token 短效（如 2 小时），Refresh Token 长效且绑定设备指纹。前端实现无感刷新（拦截 401，使用 Refresh Token 换取新 Access Token，并重放失败请求）。

    43. CSP (内容安全策略) 深度落地

    • 原理：通过 HTTP Header Content-Security-Policy 白名单控制浏览器可以加载和执行的资源。
    • 痛点解决：内联脚本（<script>）和 eval() 默认被禁。解决方案：使用 Nonce（每次请求生成随机字符串，注入到 HTML 和 CSP Header 中）或 Hash（计算脚本内容的 SHA256 加入白名单）。

    44. 拖拽排序 (DnD) 底层原理与性能优化

    • 原理：HTML5 原生 Drag and Drop API 存在诸多兼容性和交互缺陷。现代方案（如 dnd-kit, react-beautiful-dnd）通常基于 Pointer Events（鼠标/触摸统一）+ 绝对定位/transform 实现。
    • 优化：1) 拖拽时克隆一个“幽灵节点”跟随鼠标，原节点占位；2) 使用 transform 代替 top/left 触发 GPU 加速；3) 列表项使用 React.memo 避免无关项重渲染；4) 虚拟列表结合拖拽（计算复杂，需精确映射虚拟索引与真实索引）。

    45. Web Worker 与 WASM 深度应用场景

    • Web Worker：适用于 CPU 密集型任务。如：大文件 MD5 计算、复杂数据排序/过滤、音视频帧处理、加密解密。注意：Worker 无法操作 DOM，通信有序列化开销。
    • WASM (WebAssembly)：适用于对性能要求极高的计算。如：视频/图像编解码（FFmpeg.wasm）、CAD/3D 模型解析、游戏引擎（Unity/Unreal 导出）、复杂的密码学运算。

    46. 前端自动化测试体系设计

    • 分层：1) 单元测试（Jest/Vitest）：覆盖工具函数、Hooks、Redux Store；2) 组件测试（React Testing Library）：覆盖组件交互、渲染逻辑；3) E2E 测试（Playwright/Cypress）：覆盖核心业务链路（如登录、下单）。
    • 原则：测试金字塔。底层单元测试最多，E2E 最少。优先保证核心链路的 E2E 稳定性，避免测试用例过于脆弱（不测实现细节，测用户行为）。
